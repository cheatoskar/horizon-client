# Changelog

## 0.3.2 (2026-11-14)

- Horizon Performance: row **Cpu/Gpu synchro** under Smoothing. Shows what the game runs with and switches between Immediate, Half a frame and 1 Frame (tooltip: more FPS, about one frame more input delay). All five games default to Immediate: the CPU waits after every frame until the GPU has finished it, so shader mods cost their full GPU time (TMNF with TMVS: Immediate 50-70 fps, 1 Frame 90-105 fps). The switch calls the game's own `SyncGpuInit` between frames and only on exes whose viewport, method table slot and function bytes match the checked ones. ESWC, Sunrise, Original also keep it for the next start: the engine's config value and one character in `Default.SystemConfig.Gbx` next to the exe (backup once, refused on any other layout). TMNF/TMUF: this session only (their config is a compressed file in Documents; TM Horizon or TmForeverLauncher > Advanced keep it), and nothing at all with Competition Patch loaded. Every change is logged. Unit tests for the file edit (round trip, only that value changes, other layouts refused).
- **Typing in the menu respawned the car** (TMNF/TMUF): Enter and Backspace typed into a Horizon field also reached the game, which restarts or respawns on them. On TMNF/TMUF the host never held back the game's DirectInput (the game reads its keys there), and on every game a text field in a free module window (menu closed) only kept the window messages from the game. Now, whenever Horizon has the keyboard (menu, layout mode, a focused text field), no key press and no character reaches the game, neither as a window message nor through DirectInput; the release of a key the game saw go down always does, also while the menu is open, so nothing stays held. On TMNF/TMUF only the keyboard is held back (the mouse stays as it was) and only without Competition Patch: with it loaded, Horizon does nothing with the keyboard: DirectInput is not touched and every key message reaches the game (typing into Horizon fields still works). Also when Competition Patch is loaded after Horizon: the host looks for `TMCompPatch.dll` at most once a second, puts the original DirectInput functions back (a slot another hook has taken over stays a plain pass-through) and logs it once. Tests: unit tests for both gates (menu open + Enter/Backspace: the game sees nothing; menu closed: it sees its keys; release after closing: forwarded) and the same through the host's real window procedure in `host_test keys`, including a stand-in `TMCompPatch.dll` loaded after the host (slots back in `dinput8.dll`, nothing held back, every key reaches the game).
- TMNF/TMUF online showed the game state **"Editor" instead of "Online race"**: the game keeps a `CTrackManiaEditorPuzzle` in its editor slot under every race, and the host looked at that slot first. A network race is now always "Online race"; the puzzle editor under a solo race counts as that race (the rule ESWC already had), so solo runs on TMNF/TMUF also report "Solo race" and play mode solo instead of editor test (the statistics lines skipped them as editor runs). The map editor and its test drive stay "Editor". The online flag was right before and is unchanged.
- Horizon Performance: **switching the module on lowered the FPS** whenever the game ran below the frame limit (the presets limit at the monitor's refresh rate, so on a 144 Hz monitor almost always): the limiter treated a late frame as the start of a new grid and waited one whole period after it, every frame (logged: game 8.98 ms + Present 3.42 ms + limiter 6.94 ms = 52 fps instead of ~80-100). A late frame now goes at once; the limiter only waits when the game is faster than the cap. With V-Sync on and a monitor a hair slower than the cap (143.86 Hz, limit 144) the old limiter also missed every other blank (72 fps). Unit tests simulate both (10 ms frames at a 144 cap give 100 fps, V-Sync 143.86 Hz gives 143.86).
- Horizon Performance: Smooth and Low latency no longer switch on "Skip repeated states": it needs 30 hooked device methods and saves next to nothing on TMNF/TMUF (the runtime keeps the state of their mixed-VP device). A preset now hooks nothing in Direct3D; the filter stays in Custom.
- Horizon Performance: the page shows the cap in effect and whether it takes anything away ("Cap 144 fps: game below it, no wait" / "waits 2.10 ms a frame"), and while the Direct3D hooks are attached what they cost ("Hooks: 4210 hooked calls, about 0.08 ms", from a calibration at attach). The 30 s stats line in the log has the same hook figure and always the limiter's wait.
- Horizon Performance: read-only line **"Large address aware: yes/no"** for the running exe under "Engine and memory" (tooltip: 4 GB or 2 GB of memory). None of the five exes has the flag; how the launcher could set it for ESWC, Sunrise and Original (backup, one header bit, the patched hashes for the host's exe table, undo): `docs/performance-smooth.md`.
- Horizon Performance: switch **Shader cache** (Smoothing, off by default, ESWC/Sunrise/Original only): keeps the shaders the game compiles on disk (`horizon\data\performance\shadercache\<game>\`), so a map compiles nothing the second time. Hooks the exe's own `D3DXCompileShader` after checking its bytes (refused with a log line otherwise); a hit hands the engine the same bytecode with a constant table from the exe's own D3DX; a damaged file, a changed include or any failed check falls back to the normal compile. One log line per map with hits and misses. Not offered on TMNF/TMUF (Competition Patch).
- Horizon Performance: section "Smoothing" with three switches, all off by default and independent of Smooth / Low latency / Custom: **Pin thread** (the game thread on the performance cores' CPU sets, hybrid CPUs only), **Timer 1 ms** (`timeBeginPeriod(1)` and no power throttling; ESWC and Original never ask for it, their community builds patched the call out), **MMCSS** (task "Games" for the game thread). One log line per applied switch; benchmark-series options `threadCores`, `timer1ms`, `mmcss`. Static analysis of the main loop, timer, Present/GPU sync and shader creation of TMNF, ESWC, Sunrise and Original: `docs/performance-smooth.md`.
- Version 0.3.2 (`HorizonHost_Version` 0x000302).

## 0.3.1 (2026-11-12)

- Input Display 0.2.0: new style "Controller" (steering triangles left and right, filled by the steering; gas above and brake below in the middle). New installs start with the arrow keys ("Arrows", was "Keys") and without the graph; settings saved by 0.1 keep Bars and the graph. The widget is exactly as large as what it draws and has no window background: only the widget is on screen, the frame shows while the menu is open or in layout mode (new panel flag `HORIZON_PANEL_NO_BACKGROUND`). Keyboard and pad buttons are drawn as a steady on/off (a value that dropped to 0 for a frame made the bars flash); the Wheel style shows its pedal bars only for analog pedals. Outside a race nothing is drawn with the menu closed.
- Widget switch in the page header: a module with widgets (Input Display, the script widgets of Horizon Scripts, up to three) has a switch per widget next to its title, so a widget is shown or hidden without opening its tab.
- General > Menu background: the menu's opacity, 50-100 % (default 94 %, `menu.opacity` in host.json). A lower value also lightens the list and the dim layer behind the menu.
- Horizon Scripts 0.2.1: the selected script in the list is a light row with an accent bar like the menu's own lists (no orange fill); permission tags are grey; buttons and tags wrap to the next line and setting fields fit next to their labels, so nothing is cut off in a small menu.
- ABI 1.5: `suspend_widgets` hides other plugins' widgets for a while (nothing saved; back when the caller stops, is switched off or crashes). The Legacy Randomizer hides Clock and Map Info during a run. `docs/plugin-abi.md`, "ABI 1.5".
- Widgets stay on screen. Clock and Map Info (Horizon Scripts examples 1.3.0) faded out 10 s after every map load ("Hide after", default 10) and Map Info also in the game's menus, so they seemed to vanish when a map loaded. "Hide after" is now 0 (always shown) by default, Map Info shows "No map" in the menus (new setting "Hide without map", off). A value a player set stays.
- Widget places survive smaller windows: the host saved a widget's place whenever its window was somewhere else than saved, also when Dear ImGui only kept it on a smaller screen (a Reset, a loading screen, a minimised window with size 0). Now only what the player does with the mouse (menu open), layout mode and the first placement in a slot are saved; with the window large again the widget is back at its place. No panel is placed while the display has no size.
- Widget places are saved with an anchor (nearest edge per axis and the gap as a share of the window): a widget at the top right stays at the top right at any resolution and in every game; one that fits its content keeps its right or bottom edge when its content gets wider. 0.3.0 entries get their anchor at the next move, copy or export.
- Shared setup: one setup for every game install of a Windows user in `%APPDATA%\Horizon Client\shared\`. General > Shared setup (On/Off, applies after a restart; on for new installs, existing installs keep their own until switched), "Copy from this game", "Reset", "Export" / "Import" (`%APPDATA%\Horizon Client\setups\setup-<time>.json`). Per game stay the TM Horizon pairing, the login fix, free module windows and everything of modules made for some games only. Two games running at the same time merge their changes into the shared files. `docs/shared-setup.md`.
- Tests: unit test `testSharedSetup` (key classes, copy, merging saves, export/import, anchors); `host_test widgets` (the sample's Clock widget through map load, race start, checkpoint, finish, race end, next map, game menu, the Horizon menu, Resets, 1024x768 and back: always on screen, at its place) and `widgets-anchored` (the same from the shared setup, anchored to the right edge); Horizon Scripts fake host: both example widgets visible with the menu closed through a play session on all five games, on ESWC also 11 s after a map load. Test exports `HorizonHost_TestEvent`, `HorizonHost_TestPanel`, `HorizonHost_TestOverlayFault(3)` (test program only).
- Controller fix 1.2.1: a pad switched on after the game started gets its bindings at once, like a pad present at start (no restart, no wait for the next re-scan). `docs/plugins/controller-hotplug.md`. 1.2.0 read the race from the wrong app field (CTrackMania.Races instead of CConstructionGame.CurrentRace: ESWC +0x140, Sunrise/Original +0x12c), so the running race kept its table without the pad ("race table unchanged"); 1.2.1 finds it, logs why if not, and logs at every later race start how many bindings each late pad has in the new race table.
- New module Game settings 1.1.0 (ESWC, Sunrise, Original): volume, music, sounds and window mode of the game, from the Horizon menu; values are applied at every start. Window mode switches at once, with the game's own switch. Dragging a slider no longer makes the game stutter. Music changed during a race is heard when music plays again (main menu).
- Legacy Essentials: Autosave, Controller fix, the login fix and Game settings are one entry in the menu (orange gamepad icon, same name as the standalone): one switch for all, a switch per feature on its page, the modules' own pages as tabs. The DLLs stay separate; the group comes from `modules.json` next to host.dll (`packaging/modules.json`, also in `dist/manifest.json` "groups" for the launcher). On TMNF/TMUF nothing of it applies, so it is not shown. The login fix (a host feature, ESWC and Original) moved from General into the group. `docs/modules-json.md`.
- First start (new installs, no profile.json): on are Legacy Essentials (legacy games), TMX Browser and TMX Upload (only once the game is paired with TM Horizon: `"enabled_by_default": "paired"`); off are Horizon Scripts (Clock and Map Info were already hidden until shown), Input Display, WR Hunter, Performance, the Legacy Randomizer and the TM Vibrant Shaders modules unless TM Horizon switches them on (`modules.json` "defaults"). An install from before 0.3.1 keeps what 0.3.0 gave it (written once, `setup.defaults` in host.json).
- Node Explorer is a developer tool: no longer in the release packages (`package.py --dev`).
- Module icons: one set in the style of the project logos (rounded tile, darker base, stroked glyph), sources in `assets/module-icons/`, rendered by `tools/render_module_icons.mjs`.
- Toasts: a plain dark card with a thin border and a small icon, the same for every kind (no coloured edge, no badge); only an error tints its icon.
- Horizon Performance: a choice at the top of its page. Smooth (default): skip repeated states, no power throttling, priority above normal, frame limit at the refresh rate of the game's monitor, V-Sync as the game has it. Low latency: the same with V-Sync off (next start or Alt+Enter). Custom: the options one by one (High priority only there). A player who had set options before keeps them as Custom. Still off by default.
- Game state on ESWC: a campaign solo race was reported as "Editor" from map load to the end (ESWC keeps a CTrackManiaEditorPuzzle in CTrackMania.Editor for every solo race), so nothing that waits for a race or the main menu worked as meant (Randomizer, TMX Play). A puzzle editor under a solo or network race now counts as the race; the log names the editor slot's class when it changes.
- `play_map_file` on ESWC, Sunrise and Original: the copied map was never found in the game's list ("the game did not list the copy", -5 for every TMX Play and Randomizer map): the file names were read as 8-bit text, they are wide. On a miss the log shows three names it read.
- No key stays down in the game after the Horizon menu: holding a key while opening or closing the menu left it down in the game (the car kept steering). The key-up of a key the game saw go down always reaches it, and when the menu closes the game gets a key-up for every key or mouse button it still holds that is up on the device. Only releases, never a press. Unit test `testInputGate`.
- Input Display 0.1.1: on ESWC and Sunrise the player's Mobil is the car itself; the reader went one pointer further to another object whose zeros looked like "no input", so nothing moved. The car class is checked even when the offsets come by name.
- WR Hunter 0.1.1: on a map without PB or target the latest checkpoint was labelled the finish ("Finish" after CP 1, "Fin" after CP 2). The finish row now needs the finish (or a PB/target of that length); the compact line shows "CP n" while the count is unknown.
- TMX Browser 0.2.1: "Plays in the main menu" shown once (it was also in the status line).
- Other mods: the TM Vibrant Shaders modules and their tmvs-core.dll were listed and logged as "TM Vibrant Shaders" five times and their keys counted as foreign. DLLs in the host's plugins folder are modules, never other mods; a product is listed once; the game's own d3d9.dll wrapper (dgVoodoo in the Sunrise repack) is only logged.
- Leaving a race (`return_to_menu`, used by the Legacy Randomizer and TMX Play) on ESWC, Sunrise and Original went into the editor first: the race's quit button (`ButtonQuitOnClick`) is the editor's "back to editing", and every solo race on these games runs under a puzzle editor. It now does what Esc > Quit does: the race asks for the quit dialog and the host presses its Quit (the game's own handler), so the game goes straight to the menu and the next map loads. TMNF/TMUF unchanged. Read from the exes, not run in a game yet.
- TMX Browser 0.2.2: Play during a solo race (ESWC, Sunrise, Original) leaves the race and starts the map (no more "Play later" there). Forever keeps Play later.
- WR Hunter 0.1.2: TMX records of ESWC (nations.tm-exchange.com, also Nadeo maps) were "Record unreadable (no map UID in the header)": the old games write replays with the old chunk ids (header 0x2403F000, ghost 0x2401B005/0x2401B00B). The split table marks checkpoints blue and the finish red (was the orange accent).
- Game settings 1.1.1: no Sounds slider. The games' own options have Volume and Music only, and the slider was not heard on ESWC; a Sounds value saved by 1.1.0 is no longer put into the game.
- Version 0.3.1 (`HorizonHost_Version` 0x000301).
